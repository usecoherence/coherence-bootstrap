# Agent Operating Contract

Start here:

    make tool help

This repository is a Coherence-compatible Rust CLI tool generated by `coherence-generate-cli`.

## Why this repo shape exists

The goal is to reduce boilerplate and keep every Coherence CLI tool homogeneous:

- same task workflow
- same code quality gates
- same documentation policy
- same dependency checks
- same future path to external workflow orchestration
- same future path to coherence-contracts protobuf interfaces

## Normal flow

1. `make tool doctor`
2. `make tool context`
3. `make tool next`
4. `make tool plan`
5. edit code
6. `make tool run`
7. `make tool present-work`
8. `make tool feedback`

## Repository rules

- Do not create root-level Markdown files except `AGENTS.md`.
- Do not edit `docs/` manually.
- `docs/` is read-only generated output from future spec export commands.
- Specs, ACs, plans, and review contracts should be changed through tool commands once implemented.
- Tasks are tracked through beads.
- Deliverable contracts are tracked through beads-deliverables.
- Workgate may enforce write policies when available.
- This repository owns its own local Coherence DB state.
- Do not write into dependency/vendor repositories' Dolt DBs.
- Cross-repo coordination happens through links, contracts, commits, versions, releases, and future workspace indexes.
- `core-db` owns shared conventions and future workspace indexing, not one global writable DB for every repo.
- Product work belongs in local `CDB-*` (coherence-core-db) tasks.
- Reusable generator/template feedback belongs in `tasks/upstream/coherence-generate-cli.ndjson` as `CGC-RUST-*` (coherence-generate-cli) proposals.
- Do not mix `CGC-RUST-*` proposals into local beads backlog (`bd list` scope).
- Do not implement upstream proposals here unless the same change is required locally.

## Orchestration note

Workflow backend is currently `local_stub`.
Generated CLI tools expose stable local workflow commands and lightweight event/signal hook placeholders.
External `coherence-orchestrator`/`coherence-worker` may use Temporal later, but this CLI must not know Temporal server URLs, namespaces, task queues, workflow IDs, SDKs, or runtime details.

## If something is missing

Do not invent project workflow.
Run:

    make tool help

If a command prints `NOT_IMPLEMENTED`, report that honestly and continue with the nearest implemented command.
